# M3: full worker flow (target 7:30 AM)
Wire everything in agent.py using db state (survives restarts). Never block the event loop.

1. Onboarding asks only for missing profile fields, one message listing them in order:
   NAME, RATE, EMPLOYER, TITLE, STORE, MANAGER, COVER. COVER text (order matches parser: retail, over_300, works_2h_la):
   "Three yes/no questions: (1) Is your employer a retail business? (2) Does it have 300+ employees worldwide?
   (3) Is your store inside the City of Los Angeles (not Santa Monica, Culver City, Burbank, Glendale, Beverly Hills,
   Pasadena) and do you work 2+ hours a week there? Reply e.g. COVER yes yes yes". Image or SCHEDULE before onboarding is done: keep it and continue after onboarding.
2. Image -> extract(...) in to_thread; SCHEDULE block -> shifts directly. sha256 of image bytes, or of the
   normalized SCHEDULE text. db.add_version; duplicate -> "Already have this one."
3. Show shifts numbered (Tue Oct 20 1:00 PM-9:00 PM Westwood). Footer: "When did you get this schedule? If not
   today reply GOT YYYY-MM-DD. Fix with EDIT YYYY-MM-DD HH:MM-HH:MM or DROP YYYY-MM-DD. Then CONFIRM."
   GOT -> learned_at = that date 09:00 LA. EDIT/DROP update the unconfirmed version. CONFIRM -> confirmed.
4. After CONFIRM: confirmed versions in db order; diff each consecutive pair; collect events.
   rules.missing_answers -> number Q1..Qn (store mapping in profile data "questions"), ask all in one message:
   employee_requested "Did you ask for this change?", voluntary_cover "Did you volunteer to cover for a coworker?",
   misconduct "Was this cut for a disciplinary reason?". Each question names the day and change in plain words.
   ANSWER q -> db.set_answer for the mapped (event_id, field). Unknown q -> list open questions.
5. When nothing is missing (or RECEIPT): lines = rules.evaluate(events, answers, coverage, rate) +
   rules.rest_lines(latest version shifts, coverage, rate, ot). Receipt text, one line each:
   "Tue Oct 20 | shift moved | $20.00 | may be owed | OWS FWWO Rule 5" ($0 lines show their reason),
   then "Total that may be owed: $X", rules.NOT_CHECKED, "Questions: OWS (844) 924-3752".
   If total > 0: nid = db.create_notice(...) and "Reply SEND {nid} to email the official Notice to Cure to {manager}."
   If total == 0: explain why and that the saved schedules protect future changes.
6. RESET only if sender in DEMO_SENDERS. HELP anytime. Unknown text -> HELP.
7. tests/test_flow.py with a fake ctx: the golden script below must end with total $150.00 and a SEND prompt;
   two senders interleaved stay separate; restart (new process, same DB) mid-flow continues; duplicate msg ignored.
