# M4: Notice to Cure + email (target 8:15 AM)
assets/notice_to_cure.pdf is the official OWS fillable template (human downloads it from wagesla.lacity.gov).
1. notice.py: list fields with pypdf (print once, then hardcode FIELDS mapping). render_notice(profile, lines, sent_date) -> bytes:
   employee name, employer name, notice date; tick Predictability Pay if any R2/R3/R4 line, Advance Notice of Work
   Schedule if any late change, Rest Between Shifts if any R6 line; statement of facts: job title; who sets the
   schedule ("Store manager, {manager email}"); description built only from may_be_owed lines (date, change, amount,
   rule); dates; location; printed name; signature field = typed name + " (typed)"; date. Factual only.
   If a field name is missing, put everything in the description field rather than crash.
2. send(to, pdf_bytes, worker_name) -> message_id: smtplib.SMTP_SSL("smtp.gmail.com", 465, timeout=20),
   SMTP_USER/SMTP_APP_PASSWORD. Subject "Notice to Cure under the LA Fair Work Week Ordinance - {worker}".
   Body: sent at the worker's request, the 15-day cure period, "This notice was prepared with ShiftReceipt."
   Attachment Notice_to_Cure.pdf. Return the Message-ID header.
3. agent.py SEND n: if not db.claim_notice -> "That notice is not pending or the daily limit is reached."
   Else to_thread(render + send); success -> db.finish_notice(id, msg_id), reply "Sent {time}. Your employer has
   until {rules.cure_deadline(now)} to fix this. If not, you can file with OWS: wagesla.lacity.gov/complaint".
   Failure -> db.finish_notice(id, None), "Not sent. Try SEND {n} again." Never print the password.
4. Tests: rendered PDF reads back with name and total; SMTP mocked success and failure; double SEND; other sender's id.
